## 문제 요약

일렬로 나열된 집에 택배를 배달하고, 빈 재활용 택배 상자가 있으면 수거함.

배달할 택배들은 물류창고에 있고,  트럭에는 택배를 cap만큼 실을 수 있음.

배달과 수거를 모두 하고 돌아오는 최소 이동 거리 출력.

## 핵심 조건 및 제약 사항

집의 개수 → 1~100,000

cap → 1~50

트럭의 초기 위치는 물류창고

## 시행착오

맨 뒤부터 처리하면 됨.

배달 개수와 수거 개수는 따로 생각해도 됨. → 어차피 다 배달하고 수거하는게 무조건 이득이기 때문.

끝의 집의 배달과 수거를 누적해서 몇 번 왕복하면 처리할 수 있는지 계산하여 거리 계산하기.

만약에 끝에 집에 배달이3 수거가 4라면 -1/0이 되는데 이 -1은 끝에 집으로 갈 때 처리한다고 생각하여 다음 집에 자동 전파됨.

결론은 음수가 되면 알아서 갈 때(배달할 때), 돌아올 때(수거할 때) 전파가 됨.

## 구현

```java
import java.util.*;

class Solution {
    public long solution(int cap, int n, int[] deliveries, int[] pickups) {
        long answer = 0;
        
        int d = 0;
        int p = 0;
        for(int i=n-1; i>=0; i--){
            d += deliveries[i];
            p += pickups[i];
            
            int cnt = 0; //왕복 횟수
            while(d > 0 || p > 0){ //현재 집을 다 처리할 수 있을 때 까지
                d -= cap;
                p -= cap;
                cnt++;
            }
            
            //이동거리 추가
            answer += (long)(i+1) * 2 * cnt;
        }
        
        return answer;
    }
}
```

## 회고

처음에는 배달과 수거를 합쳐서 트럭 용량을 조절해야 한다고 생각하여 로직이 많이 꼬였었다. 

하지만 이 문제는 갈 때 배달 `cap`개, 올 때 수거 `cap`개를 온전히 따로 쓸 수 있는 시차가 존재하는 문제였다. 

어차피 가장 먼 집을 가려면 가까운 집들을 무조건 지나쳐야 하므로, 배열을 뒤에서부터 거꾸로 계산하며 생기는 음수 값들은 현실에서 '가는 길에 미리 내린 배달'과 '돌아오는 길에 미리 실은 수거'를 의미하게 되는 것이었다. 

결론적으로 가장 먼 집을 방문하며 생긴 용량의 여유(음수)가 가까운 집들의 요구량을 알아서 해결하며 전파되므로, 음수 상태일 때는 추가 거리 계산 없이 패스하면 되는 깔끔한 그리디 문제였다.
