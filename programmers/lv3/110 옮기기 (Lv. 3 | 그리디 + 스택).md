## 문제 요약

110을 뽑아서 임의의 위치에 다시 삽입

변형에서 만들 수 있는 문자열 중 사전 순으로 가장 빠른 문자열을 반환

##  핵심 조건 및 제약 사항

문자열 개수 → 1 ~ 1,000,000

문자열 길이 → 1 ~ 1,000,000
근데 모든 문자열 길이 합이 1,000,000보다 작음.

## 시행착오

110이라는 숫자를 어디에 넣어야 사전 순으로 가장 빠른 문자열인지 생각을 해보았을 때

맨앞이 1이기 때문에 맨 오른쪽에 있는 0뒤에 오는게 제일 좋음

근데 만약 0이 하나도 없다면 맨 끝이 0이기 때문에 맨 앞에 오는게 좋음 → 111110 보단 110111이 더 빠른 것 처럼.

110을 빼서 위에 생각한대로 붙이기 → 뺄 때 또 만들어지는 110 계속 빼기 → 어차피 또 빼기전에 110을 다시 넣는 다 해도 결과물은 같음. 110 끼리는 서로 영향을 줄 수 없기 때문

## 구현

```java
import java.util.*;

class Solution {
    public String[] solution(String[] s) {
        String[] answer = new String[s.length];
        
        for(int i=0; i<s.length; i++){
            String str = s[i];
            LinkedList<Character> stack = new LinkedList<>();
            int cnt = 0; //110 개수
            for(int j=0; j<str.length(); j++){
                stack.push(str.charAt(j));
                if(stack.size() >= 3 && stack.get(0) == '0' && stack.get(1) == '1' && stack.get(2) == '1'){
                    stack.pop();
                    stack.pop();
                    stack.pop();
                    cnt++;
                }
            }
            
            StringBuilder sb = new StringBuilder();
            for(char c : stack){
                sb.append(c);
            }
            sb.reverse();
            
            int index = sb.lastIndexOf("0");
            sb.insert(index+1, "110".repeat(cnt));
            //0이없으면 -1을 반환하는데 -1+1 = 0이 돼서 0이 없는 문자열에서는 알아서 맨 앞으로 쏙 들어감
            
            answer[i] = sb.toString();
        }
        
        return answer;
    }
}
```

## 회고

자바 자료구조중 스택에 대해 헷갈렸다. push와 pop은 왼쪽에서 넣기 때문에 끝에는 가장 맨 처음에 넣었던 것이 존재한다.

ArrayDeque는 인덱스를 관리하지 않는다. 따라서 스택에서 인덱스도 활용할꺼면 LinkedList를 사용하자.

앞으로 사전 순 최적화 문제가 나오면 그리디를 생각해보자.

특정 문자 패턴을 지우고 남은 문자열을 이어 붙인다 라는 규칙이 보이면 스택을 생각해보자.
