## 문제 요약

낚시왕이 오른쪽으로 한칸 씩 이동하는 데 같은 열에 있는 땅과 제일 가까운 상어를 잡는다.

상어는 낚시왕이 한 칸 이동한 후 움직인다.

상어는 주어진 속도가 있고 방향이 있는데 벽에 닿는 경우 반대로 속력을 유지한채 이동한다.

상어가 이동을 마친 후 같은 칸에 두 마리 이상 있을 경우 크기가 제일 큰 상어가 나머지 상어를 모두 잡아 먹는다.

낚시왕이 잡은 상어 크기의 합을 구하라.

## 핵심 조건 및 제약 사항

배열 크기 최대 100x100

상어수 0~10000

상어 위치 주어지고 속력은 0~1000, 방향 4방향, 크기 1~10000

## 시행착오

바깥쪽 반복문은 낚시왕이 해당 열에서 가장 가까운 상어를 잡는 걸로 하고,

안쪽 반복문은 상어들이 움직이는 걸 수행.

배열안에서만 상어를 이동시키기엔 해당 상어가 어떤 정보를 가지고 있는지 모르기때문에 상어 클래스를 따로 만들어 배열 생성.

매번 배열을 돌며 상어의 위치를 확인 하지 않기 위해 살아있는 상어들만 모아놓은 리스트 활용.

상어를 한 칸씩 이동시키다가 벽을 만났을 시 방향 바꾸고 하는걸 최대한 줄이기 위해 왕복이 얼마나 되는지 구해서 사용. 나머지를 직접 이동시키기.

이동시킬 때마다 갱신하기 힘드니 임시 배열 하나 만들어서 이동했을 때를 넣고 나중에 덮어 씌우기.

이동시킬 때마다 해당 칸에 상어가 있으면 비교하여 갱신.

## 구현

```java
import java.util.*;
import java.io.*;

class Shark{
	int r;
	int c;
	int s;
	int d;
	int z;
	
	public Shark(int r, int c, int s, int d, int z) {
		this.r = r;
		this.c = c;
		this.s = s;
		this.d = d;
		this.z = z;
	}
}

public class Main{
	public static void main(String[] args) throws IOException{
		BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
		
		StringTokenizer st = new StringTokenizer(br.readLine());
		int R = Integer.parseInt(st.nextToken());
		int C = Integer.parseInt(st.nextToken());
		int M = Integer.parseInt(st.nextToken());
		
		Shark[][] arr = new Shark[R+1][C+1];
		List<Shark> list = new ArrayList<>();
		for(int i=0; i<M; i++) {
			st = new StringTokenizer(br.readLine());
			int r = Integer.parseInt(st.nextToken());
			int c = Integer.parseInt(st.nextToken());
			int s = Integer.parseInt(st.nextToken());
			int d = Integer.parseInt(st.nextToken());
			int z = Integer.parseInt(st.nextToken());
			Shark shark = new Shark(r, c, s, d, z); // 객체 하나 생성
		    arr[r][c] = shark; // 배열에 넣기
		    list.add(shark);   // 동일 객체 리스트에 넣기
		}
		
		int answer = 0;
		for(int i=1; i<=C; i++) { //낚시왕은 열의 수 만큼 움직임
			//i번째 열에서 가까운 물고기 잡기
			for(int j=1; j<=R; j++) { //행 살피기
				if(arr[j][i] != null) { //비어있지 않은 제일 먼저 만나는 물고기 잡음
					answer += arr[j][i].z;
					list.remove(arr[j][i]); //리스트에서 지우고
					arr[j][i] = null; //해당 위치 null로 만들기
					break; //한마리 잡았으니 끝
				}
			}
			
			//상어 이동 시작. 원래 배열에 상어를 없애고 이동한 위치에 다시 생성하고 할 필요 없이
			//이동한 상어들을 담고 덮어씌우면 됨.
			//배열을 돌며 상어가 어디있는지 확인하지 않고 리스트를 활용하여 바로바로 처리함.
			Shark[][] temp = new Shark[R+1][C+1];
			
			for(int j=0; j<list.size(); j++) { //상어 수 만큼 반복 -> 상어수가 줄어들 수 있어 list.size()만큼으로 돌려야됨!!
				Shark cur = list.get(j);
				
				//왕복 거리 계산해서 반복문 최대한 줄이기
				int mod = 0;
				if(cur.d == 1 || cur.d == 2) mod = (R-1) * 2;
				else mod = (C-1) * 2;
				
				//속력을 왕복으로 나눈 나머지 만큼만 이동할거임.
				int move = 0;
				if(mod != 0) move = cur.s % mod;
				
				for(int k=0; k<move; k++) {
					//양 끝 지점에 있으면 방향전환
					if(cur.d == 1 && cur.r == 1) cur.d = 2;
					else if(cur.d == 2 && cur.r == R) cur.d = 1;
					else if(cur.d == 3 && cur.c == C) cur.d = 4;
					else if(cur.d == 4 && cur.c == 1) cur.d = 3;
					
					//이동
					if(cur.d == 1) cur.r--;
					else if(cur.d == 2) cur.r++;
					else if(cur.d == 3) cur.c++;
					else if(cur.d == 4) cur.c--;
				}
				
				//이동 후 갱신
				//비어있다면 넣기
				if(temp[cur.r][cur.c] == null) temp[cur.r][cur.c] = cur;
				
				//비어있지 않다면 크기 비교후 갱신
				else if(temp[cur.r][cur.c].z < cur.z) temp[cur.r][cur.c] = cur;
			}
			
			//전체 상태 갱신
			arr = temp;
			//잡아먹으면서 리스트를 갱신하기엔 복잡함
			//지금 배열에 살아있는 상어를 기준으로 리스트를 새로 구성
			list.clear();
			for(int r=1; r<=R; r++) {
				for(int c=1; c<=C; c++) {
					if(arr[r][c] != null) list.add(arr[r][c]);
				}
			}
		}
		
		System.out.println(answer);
	}
}
```

## 회고

처음에는 데이터를 어떻게 관리할지 고민했는데, 낚시왕이 상어를 낚을 때는 좌표 기반인 배열이 유리하고, 상어를 이동시킬 때는 살아있는 개체만 모아둔 리스트가 효율적이라는 것을 깨달으면서 공간과 목록을 이분법적으로 설계했다.

가장 큰 어려움은 상어의 속력이었다. 수천 번의 이동을 일일이 계산하면 시간 초과가 날 게 뻔했다. 1000의 속력, 10000마리의 상어, 100번의 낚시왕 이동 → 10억번에 가까운 연산이 발생할 것이다.
그래서 상어가 제자리로 돌아오는 왕복주기를 구해 속력을 나눈 나머지만큼만 직접 이동시키는 최적화를 적용했다. 이때 상어들이 동시에 움직이는 효과를 내기 위해 임시 배열을 만들어 이동 완료된 상태를 따로 담았고, 그 과정에서 같은 칸에 겹치는 상어 중 가장 큰 놈만 남기는 것을 구현하며 상태 꼬임 문제를 해결했다.

결국 포획할 때마다 리스트를 갱신하고 인덱스 범위를 조절하며, 0으로 나누는 에러 같은 엣지 케이스까지 다듬고 나서야 잘 풀 수 있었다.
