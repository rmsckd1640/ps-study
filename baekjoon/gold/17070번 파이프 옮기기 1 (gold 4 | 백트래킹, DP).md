## 문제 요약

파이프를 옮길것이다.

파이프를 밀 수 있는 방향은 총 3가지 →, ↘, ↓ 방향이다. 밀면서 회전 시킬 수 있다. 회전은 45도만 회전 가능.

파이프가 가로로 놓여진 경우에 가능한 이동 방법은 총 2가지, 세로로 놓여진 경우에는 2가지, 대각선 방향으로 놓여진 경우에는 3가지가 있다.

가장 처음에 파이프는 (1, 1)와 (1, 2)를 차지하고 있고, 방향은 가로이다. 파이프의 한쪽 끝을 (N, N)로 이동시키는 방법의 개수를 구해보자.

## 핵심 조건 및 제약 사항

집의 크기 N → 3 ~ 16

행과 열의 번호는 1부터 시작.

파이프가 벽을 긁으면 안 됨.

빈칸은 0, 벽은 1로 주어짐. (1, 1)과 (1, 2)는 항상 빈 칸이다.

이동시킬 수 없는 경우에는 0을 출력한다.

방법의 수는 항상 1,000,000보다 작거나 같다.

## 시행착오

한쪽 끝이 어떻게 왔는지에 따라서 갈 수 있는 방향이 정해짐. → 어떤 상태인지도 갖고 가야됨.

모든 방법의 수를 다 구해야함 → 백트래킹

방향배열 반복문 돌릴 때 가로일 때랑 세로일 때 하나씩 못가는 경우 어떻게 처리하지? → 7가지 경우중 2가지 뿐이니 반복문 안에서 조건문으로 처리

대각선일 때 한번에 조건문 처리하니 틀림 → 한번에 했을 때 대각선일때 틀리면 탐색하면 안되는데 else문 타고 들어가버림 → 조건문을 한번에 처리하지 말고 대각선일 때 또 안으로 들어가서 조건문을 걸면 else일 때 아무것도 안함.

## 구현(백트래킹)

시간복잡도: 이론상 2N칸 및 각 칸마다 3방향 → $O(3^{2n})$ → 가지치기 덕분에 문제 범위 조건 안에서 가능.

```java
import java.util.*;

public class Main{
	//가로 세로 대각선 순서 (상태도 가로 세로 대각선 순으로 0, 1, 2)
	static int[] dx = {0, 1, 1};
	static int[] dy = {1, 0, 1};
	static int n;
	static int[][] arr;
	static int answer = 0;
	
	public static void DFS(int x, int y, int status) {
		if(x == n-1 && y == n-1) {
			answer++;
			return;
		}
		else {
			for(int i=0; i<3; i++) {
				//세로일 때 가로로 못감
				if(i == 0 && status == 1) continue;
				
				//가로일 때 세로로 못감
				if(i == 1 && status == 0) continue;
				
				int nx = x + dx[i];
				int ny = y + dy[i];
				
				if(nx >= 0 && nx < n && ny >= 0 && ny < n && arr[nx][ny] == 0) {
					//i가 다음 상태임.
					if(i == 2) {
						//이렇게 나눠야 대각선일 때 조건 충족 안하면 탐색안함
						if(arr[nx-1][ny] == 0 && arr[nx][ny-1] == 0) DFS(nx, ny, i);
					}
					else {
						DFS(nx, ny, i);
					}
					
				}
			}
		}
	}
	
	public static void main(String[] args) {
		Scanner sc = new Scanner(System.in);
		n = sc.nextInt();
		arr = new int[n][n];
		for(int i=0; i<n; i++) {
			for(int j=0; j<n; j++) {
				arr[i][j] = sc.nextInt();
			}
		}
		
		//처음 시작은 (0,1) 그리고 가로방향 0
		DFS(0, 1, 0);
		
		System.out.println(answer);
	}
}
```

## 추가구현 (DP)

N이 커질경우 시간초과 → DP

중복 부분 문제 → 똑같은 좌표로 도달하는 경로가 여러개
최적 부분 구조 → 목표까지 가는 방법의 수가 결국 그 이전 칸들까지 오는 방법의 수들의 합으로 결정.

DP 설계 3단계

1. 무엇을 기록할 것인가?
2. 점화식 세우기
3. 초기값 및 채우는 순서

어떤 방향에서 왔느냐에 따라 다음 동작이 제한 되기 때문에 3중배열 사용.
(예를 들어 가로로 올꺼다? 전의 형태가 가로이거나 대각선이어야 한다.)

처음에 `if(i-1 >= 0 && j-1 >= 0)`으로 어떤 이동이든 다 묶었는데 이렇게 되면 예를 들어 가로 이동이면 i가 0일때도 가로로 이동할 수 있어야하는데 이 조건때문에 무시된다.
→ 따라서 각 이동마다 다 나누는게 좋다.

반복문에서 시작점도 제외 시켜야한다. 시작점도 포함시킬경우 `dp[0][0][0]` 때문에 개수가 1로 저장된 시작점이 0으로 덮어씌워지기 때문이다.
그럼 `dp[0][0][0]`이거도 1로 해놓으면 되지 않냐? → DP를 파이프의 오른쪽 끝의 상태를 기준으로 정의했다. `dp[0][0][0]`도 1로  할 경우 (0, 0)에 오른쪽 끝이 있고 왼쪽 끝은 격자 밖에 있는 유효하지 않은 상태에서 시작하는 셈이다.

```java
import java.util.*;

public class Main{
	public static void main(String[] args) {
		Scanner sc = new Scanner(System.in);
		int n = sc.nextInt();
		int[][] arr = new int[n][n];
		for(int i=0; i<n; i++) {
			for(int j=0; j<n; j++) {
				arr[i][j] = sc.nextInt();
			}
		}
		
		int[][][] dp = new int[n][n][3]; //0 가로, 1 세로, 2 대각선
		
		dp[0][1][0] = 1; //시작점
		
		for(int i=0; i<n; i++) {
			for(int j=0; j<n; j++) {
				
				
				//시작점도 제외하여 dp[0][0][0]의 값이 덮어씌는 것 방지
				if((i == 0 && j == 1) || arr[i][j] == 1) continue;
				
				//1. 가로로 오는 경우 -> 오기 전 형태가 가로, 대각선이어야 가로로 올 수 있음.
				if(j-1 >= 0) dp[i][j][0] = dp[i][j-1][0] + dp[i][j-1][2];
				
				//2. 세로로 오는 경우 -> 오기 전 형태가 세로, 대각선
				if(i-1 >= 0) dp[i][j][1] = dp[i-1][j][1] + dp[i-1][j][2];
				
				//3. 대각선으로 오는 경우 -> 전부 다 가능
				//대각선인 경우 벽 추가로 확인
				if(i-1 >= 0 && j-1 >= 0 && arr[i-1][j] == 0 && arr[i][j-1] == 0) {
					dp[i][j][2] = dp[i-1][j-1][0] + dp[i-1][j-1][1] + dp[i-1][j-1][2];
				}
			}
		}
		
		int answer = dp[n-1][n-1][0] + dp[n-1][n-1][1] + dp[n-1][n-1][2];
		System.out.println(answer);
	}
}
```

시간복잡도: $O(n^2)$

### 만약 BFS로 푼다면 어떻게 될까?

BFS는 모든 이동 상태를 객체로 만들어 큐에 삽입.

백트래킹은 단순 재취 호출로 해결되지만 BFS는 수백만 개의 객체를 힙 메모리에 할당하고 해제하는 과정을 거치며 CPU 자원을 많이 소모. 이 과정에서 GC가 빈번하게 발생하여 실행 시간이 대폭 늘어남.

백트래킹은 현재 탐색 중인 경로 하나만 메모리에 유지하면 되지만 BFS는 현재 단계에서 가능한 모든 선택지를 큐에 한꺼번에 담아줌.
이렇게 되면 방문 처리를 통해 탐색을 제한할 수 없음.

결과적으로 큐에 쌓이는 상태 객체가 기하급수적으로 늘어나면서, 메모리가 감당하지 못하고 터져버리는 상황이 발생할 위험이 매우 큼.

결론: 다 뒤져보는 건 똑같지만, BFS는 방문 처리를 못 하는 순간 수백만 개의 객체를 큐라는 보따리에 한꺼번에 싸들고 있으려다 메모리가 터져버리는 비효율적인 탐색이 된다.
